O que é Arquitetura de Software?

Analogia Prática do Dia a Dia

Pensando Software como a Construção de uma Casa 🏠

Imagine que você vai construir um prédio ou uma casa. Antes de escolher a cor das paredes ou comprar os móveis (que seria a *interface* do aplicativo), você precisa responder a perguntas estruturais cruciais:

  • Fundação & Vigas: O prédio aguenta 10 andares no futuro? (Escalabilidade)
  • Sistema Hidráulico e Elétrico: Como a água e a energia vão fluir pelos cômodos? (Comunicação)
  • Segurança: Onde ficam as portas de emergência e trincas? (Segurança da Informação)

Arquitetura de Software é exatamente isso! É o conjunto de decisões estruturais de alto nível que são difíceis de mudar depois que o projeto está pronto.

Por que a Arquitetura importa?

Manutenibilidade

Fácil de arrumar defeitos.

Escalabilidade

Cresce de 100 para 1M de usuários.

Segurança

Protege dados confidenciais.

Organização

Vários devs trabalham juntos.

Principais Modelos Arquiteturais

Tudo em um só lugar

Monólito (Monolithic)

Todo o aplicativo (interface, lógica, banco de dados) fica dentro de um único bloco de código gigantesco.

👍 Vantagem: Simples de criar e testar no início.

👎 Desvantagem: Se uma parte quebrar, o sistema todo cai.

Exemplo: Um sistema web pequeno de escola.
Mais Tradicional

Arquitetura em Camadas (Layered)

O código é dividido em responsabilidades: Apresentação, Lógica de Negócios e Banco de Dados.

👍 Vantagem: Organizado, modular e fácil de entender.

👎 Desvantagem: Altera-se uma camada, pode afetar outras.

Exemplo: Padrão MVC em sistemas comerciais.
Alta Escala

Microsserviços (Microservices)

O sistema é quebrado em vários pequenos programas independentes que se comunicam via rede.

👍 Vantagem: Se um serviço cair, os outros continuam rodando.

👎 Desvantagem: Muito mais complexo de gerenciar.

Exemplo: Netflix, Uber, Mercado Livre.

Diagramas UML Essenciais

Unified Modeling Language — A linguagem visual padrão mundial da engenharia de software.

O que é a UML?

A UML é como o "Blue Print" (planta baixa) que os arquitetos usam. Em vez de escrever páginas de texto descrevendo o código, usamos símbolos e mapas gráficos padrão para que qualquer programador do mundo entenda como o sistema funciona.

4 Principais Diagramas cobrem 90% das necessidades no dia a dia.
Comportamento & Requisitos

1. Diagrama de Casos de Uso (Use Case Diagram)

Mostra QUEM (Atores) usa o sistema e O QUE (Ações/Funcionalidades) eles podem fazer. É ideal para conversar com o cliente antes de programar.

Elementos Chave

  • 👤 Ator (Boneco): Quem interage (usuário, sistema externo).
  • ⭕ Ovo / Elipse (Caso de Uso): A funcionalidade (ex: "Sacar Dinheiro").
  • 🔲 Retângulo (Limite): A fronteira do sistema.

Exemplo Prático do Dia a Dia

Pense num aplicativo do iFood: O Ator "Cliente" realiza os Casos de Uso "Buscar Restaurante", "Adicionar ao Carrinho" e "Pagar". O Ator "Entregador" realiza "Aceitar Entrega".

Estrutura Estática

2. Diagrama de Classes (Class Diagram)

O mais famoso da UML! Mostra a estrutura interna das "peças" do sistema: os Atributos (dados), Métodos (ações) e as Relações entre elas.

Símbolos de Visibilidade:

+ Público (Qualquer um acessa)
- Privado (Só a própria classe)

Exemplo Prático

Pense na ficha cadastral de um aluno: Os dados (Nome, CPF) são os Atributos. As ações que ele faz (Matricular, Trancar Curso) são os Métodos.

Comunicação Temporal

3. Diagrama de Sequência (Sequence Diagram)

Mostra como os componentes do sistema conversam entre si ao longo do tempo, passo a passo, em ordem cronológica de cima para baixo.

💡 Quando usar? Sempre que você precisar explicar como funciona um processo complexo que envolve troca de mensagens em tempo real, como um pagamento com cartão de crédito.
Fluxo de Processos

4. Diagrama de Atividades (Activity Diagram)

Funciona como um Fluxograma avançado. Mostra o passo a passo de um algoritmo ou processo de negócio, incluindo decisões (SE / SENÃO).

💡 Resumo Didático: Círculo preto = Início/Fim. Losango = Tomada de decisão (caminhos bifurcados). Retângulos arredondados = Ações executadas.

O Padrão MVC (Model - View - Controller)

O padrão de arquitetura mais famoso do desenvolvimento web mundial.

A Analogia Perfeita

Como o MVC funciona como um Restaurante 🍽️

Se você entender como funciona um restaurante moderno, você já entendeu o padrão MVC!

🖥️
V - View

O Cardápio e a Mesa

É a Interface com o Usuário (UI). O que o cliente vê na tela (botões, HTML, cores, formulários). Ela exibe as informações e captura os cliques.

"O cliente escolhe o prato no cardápio."
🤵
C - Controller

O Garçom (Cérebro/Roteador)

É a Lógica de Controle. Ele recebe o pedido do cliente (View), leva até a cozinha (Model), pega o prato pronto e traz de volta para a mesa.

"Anota o pedido e coordena o fluxo."
👨‍🍳
M - Model

A Cozinha e o Estoque

É o Banco de Dados e Regras de Negócio. Onde a comida é preparada de verdade, onde os ingredientes são guardados e onde as receitas são validadas.

"Prepara os dados e regras de negócio."

O Fluxo de Dados no MVC (Passo a Passo)

1
Ação do Usuário

Usuário clica num botão na View (ex: "Comprar").

2
Controller Recebe

O Controller interpreta o clique e pede ao Model para processar.

3
Model Processa

O Model grava no Banco de Dados e valida as regras.

4
View Atualiza

O Controller recebe a resposta e manda a View renderizar a confirmação.

Como fica no Código de Verdade?

Exemplo simplificado de um cadastro de produto dividindo o código em 3 arquivos organizados:

ProdutoModel.js MODEL 
// Regras & Banco de Dados
class ProdutoModel {
  async salvar(nome, preco) {
    if (preco <= 0) {
      throw Error("Preço inválido");
    }
    // Salva no banco de dados SQL
    return await db.insert({ nome, preco });
  }
}
ProdutoController.js CONTROLLER 
// O Intermediário / Lógica
async function cadastrar(req, res) {
  const { nome, preco } = req.body;
  
  // Chama o Model
  const novoProduto = await ProdutoModel.salvar(nome, preco);
  
  // Responde para a View
  res.render('sucessoView', { produto: novoProduto });
}
produtoView.html VIEW 
<!-- O que o usuário vê -->
<div class="card">
  <h1>Produto Cadastrado!</h1>
  <p>Nome: {{produto.nome}}</p>
  <p>Preço: R$ {{produto.preco}}</p>
</div>
